# VIO · Телевидение

Независимое русскоязычное IPTV-приложение для телевизора. Только телеканалы: категории, список, просмотр справа, полноэкранный режим, избранное, последний канал и крупный простой режим. Старый каталог с фильмами, сериалами и внешними подписочными плеерами заменён полностью.

## Версия 1.1: просмотр внутри MSX и EPG по умолчанию

MSX теперь открывает **нативные JSON-страницы** через Interaction Plugin, без перехода в браузер. Список каналов, категории, избранное, крупный режим, последний канал и настройки находятся в MSX. Встроенный Video Plugin показывает поток справа, OK раскрывает его на весь экран, Назад возвращает список. Для мини-плеера нужна MSX 0.1.167 или новее. Резервный встроенный плеер MSX также запускается внутри приложения.

EPG по умолчанию: **http://epg.it999.ru/epg2.xml.gz**. Gzip распаковывается и XMLTV разбирается потоком, без хранения полного XML в памяти. Для просмотра сохраняются передачи подходящих каналов за последние 6 часов и следующие 72 часа. Обновление — в фоне при запуске, после импорта плейлиста и раз в 6 часов. Существующий пользовательский URL EPG не заменяется. Обычная внешняя декларация XMLTV DTD удаляется без обращения к внешним файлам; пользовательские ENTITY и внутренние DTD запрещены.

Сопоставление EPG — по tvg-id; при его отсутствии по однозначному совпадению tvg-name или названия канала с display-name в XMLTV. Неоднозначные совпадения не назначаются. Совпадение названий не гарантируется для всех каналов. Статус фоновой загрузки и ошибка видны в админке.

### Обновление уже установленного NAS

В папке свежих исходников выполните **sudo sh deploy/update.sh**. Скрипт сначала собирает новый образ, сохраняет текущие переменные контейнера во временный закрытый файл, использует существующий volume vio-data и оставляет предыдущий контейнер как резервный. Плейлист, EPG и хеш пароля не сбрасываются. После запуска проверяется здоровье; при ошибке запуска возвращается предыдущий контейнер. На NAS с нестандартным volume обновление останавливается.

В MSX укажите стартовый параметр **192.168.8.222:8088**. Прежний id:igd:vioiptv также указывает на нативный Interaction Plugin на этом NAS. Веб-страница /admin предназначена для управления с компьютера.

## Что входит

- **ТВ-пульт MSX / браузер:** Дополнительный HTML-интерфейс с крупным фокусом, стрелками, OK и Назад. Первое OK включает канал справа, повторное OK раскрывает его на весь экран. HLS через hls.js, нативный HTML5 для других поддерживаемых потоков.
- **Android TV APK:** Kotlin / Media3 ExoPlayer, HLS, MPEG-TS и поддерживаемые устройством кодеки; настройки языка звука, субтитров, ограничения до 720p, масштаба, запуск резервного внешнего плеера. Избранное и последний канал хранятся на устройстве.
- **API и админка:** импорт M3U/M3U8 из файла или URL, категории, XMLTV EPG с текущей и следующей передачей, ручное обновление сохранённых URL, смена пароля. Scrypt с солью, часовые сессии, отзыв при смене пароля, ограничение входа. Импорт URL защищён от обращений к приватным адресам и DNS rebinding; локальные источники загружайте файлами.
- **MSX JSON:** стартовый объект и совместимые страницы, плюс нативный постраничный список каналов на сервере. Просмотр работает на нативных страницах MSX через Interaction и Video Plugins.
- **NAS:** Docker Compose, постоянный volume и проверка здоровья. Рабочий адрес после установки: `http://192.168.8.222:8088`.

## Подключение на телевизоре

В Media Station X: **Settings → Start Parameter → Setup → `id:igd:vioiptv` → подтвердить VIO**. Адрес сохранён. Он загружает ТВ-стартовую страницу с GitHub, и сразу загружает нативный экран каналов из NAS внутри MSX. Пока контейнер не установлен на NAS, эта кнопка не может показать ваши каналы.

Можно подключиться напрямую: стартовый параметр MSX **`192.168.8.222:8088`**. Для HTTPS нужен доверенный сертификат и соответствующий PUBLIC_URL. Стартовый объект загружает Interaction Plugin, который формирует нативный список и встроенный мини-плеер. Поддержка HTML/HLS/кодеков зависит от MSX и прошивки телевизора.

## Установка

Полная инструкция: [deploy/NAS.md](deploy/NAS.md). Панель NAS `:8001/portal/` не является VIO.

Локальная разработка: Node.js 22 или 24, `npm ci`, `npm run build`, задайте переменную `VIO_ADMIN_PASSWORD`, затем `npm start`. Сервер слушает порт 8080. Первоначальный пароль не задан в исходниках. При первом запуске нужен пароль от 8 символов; затем его можно изменить в админке. Не публикуйте личные плейлисты и `.env`.

Для Docker скопируйте `.env.example` в `.env`, задайте начальный пароль, выполните `docker compose up -d --build`.

## Android и автозапуск

В [GitHub Actions](https://github.com/vioproduct1-sudo/VIO/actions) откройте успешный **VIO CI** и скачайте **VIO-debug-apk**. Это APK с отладочной подписью для тестовой установки. Для публичного выпуска нужна отдельная release-подпись, которой в репозитории нет.

Настройки → сервер VIO. Переключатель «Автозапуск после загрузки» использует BOOT_COMPLETED и работает только там, где ОС разрешает запуск. Поддерживаемая альтернатива — «Выбрать VIO домашним экраном»: приложение включает HOME alias и открывает системный выбор launcher. Выбор подтверждает владелец устройства. Кнопка отключения launcher также доступна.

**Принудительный запуск поверх системных ограничений не реализован.** Android 10+ и производители ограничивают фоновый запуск; без прав device owner / системных прав гарантировать его нельзя. После принудительной остановки приложения автозапуск может не сработать до ручного открытия. Реальная приставка нужна для проверки BOOT_COMPLETED, launcher, пульта, декодеров и HDMI.

## API

- GET `/health` — состояние.
- GET `/api/channels` — каналы и now/next; доступен устройствам домашней сети.
- POST `/api/login` — пароль, ответ с bearer token и HttpOnly cookie.
- GET `/api/admin/status` — количество каналов и передач.
- POST `/api/admin/import` — `m3u` / `playlistUrl`, `xmltv` / `epgUrl`.
- POST `/api/admin/refresh` — ручное обновление сохранённых URL.
- POST `/api/admin/password`, `/api/admin/logout` — смена пароля и выход.
- GET `/msx/start.json`, `/msx/channels.json` — встроенный интерфейс MSX.

## Проверки и границы MVP

`npm run build && npm test`: парсинг M3U/XMLTV, ограничения удалённой загрузки, защита админки, отзыв сессий, сохранность базы, now/next, избранное, категории и ТВ-only JSON. CI также проверяет зависимости, Docker и Android assembleDebug/lintDebug, публикует **VIO-NAS** и **VIO-debug-apk**.

Нет встроенных чужих каналов: администратор подключает свой плейлист. Поддерживаются HTTP(S) URL. Нет DRM, RTSP/UDP, catch-up, архивов, VOD-каталога, прокси и транскодирования. XMLTV из файла принимается как UTF-8 до 20 МБ. URL .xml.gz обрабатывается потоково с пределом 800 МБ распакованных данных и 150 тысяч подходящих передач. M3U — до 6 МБ. Звук/качество в веб-плеере доступны для дорожек и вариантов HLS; аппаратный passthrough выбирает система устройства.

Мини-плеер справа — часть интерфейса, отдельный системный Picture-in-Picture не заявлен. Настройки и избранное не синхронизируются между устройствами. Сервер ещё требуется установить на NAS; публикация GitHub сама по себе его не запускает.

Права: исходники MIT. hls.js — Apache-2.0, лицензия копируется в web/vendor при сборке; остальные зависимости указаны в package-lock.json.

## Экран MSX 1.1.1

Оформление по образцу: тёмно-синий фон, бирюзовое выделение, 22 строки каналов слева и окно просмотра справа. Крупный режим показывает 8 строк. SVG служит визуальным слоем; выбор остаётся настоящими элементами MSX. После перемещения фокуса логическая сетка перестраивается, чтобы стрелки вверх/вниз выбирали соседнюю строку. Это требует работающего NAS и может давать задержку при быстром пролистывании. Избранное добавляется через «Настройки → ★ Добавить / убрать выбранный канал».

Проверено оформление и последовательный выбор в официальном MSX 0.1.167 web. Реальные потоки, полный экран, возврат к списку и совместимость SVG/плеера с UWP 0.1.167 и телевизорами требуют проверки на устройстве; серверные тесты их не подтверждают. Не заявляется полная идентичность веб- и UWP-движков.

Обновление существующей установки: скачайте main.tar.gz, распакуйте в ~/vio-install и выполните `sudo sh deploy/update.sh` в VIO-main. Скрипт сохраняет том vio-data с плейлистом и паролем, сохраняет старый контейнер для отката.

## Воспроизведение 1.1.2

В плеере VIO целевой HLS-буфер увеличен до 45 секунд, максимум 90 секунд и 60 МБ, история 15 секунд. Для прямого эфира выбрана точка в четырёх фрагментах от края; это увеличивает задержку относительно эфира. Значения не означают обязательного ожидания всего буфера перед запуском. Если HTML video поддерживает HLS, сначала используется нативная загрузка. При фатальной сетевой ошибке выполняется одна передача во встроенный MSX, при ошибке декодирования допускается одно восстановление. Таймер отсутствия прогресса 20 секунд сначала возобновляет HLS-загрузку, затем при повторном зависании передаёт поток MSX. Пауза пользователя и уничтожение плеера отменяют восстановление. Размер буфера встроенного Windows/MSX-плеера этими значениями не регулируется.

Переход между полноэкранным режимом и списком не останавливает плагин из-за промежуточного скрытого состояния. Для кнопки Назад задано возвращение к контенту. Проверки выполняют сценарии с имитацией video, SDK и времени; качество реального потока и поведение кнопки Назад после установки требуется проверить в UWP.

## Ключ доступа iEdem.tv · 1.1.3

В админке есть отдельная форма ключа из раздела «Доступ» iEdem.tv. Она заменяет сегмент ключа в HTTP(S)-адресах вида /iptv/KEY/канал, сохраняя ID, имена, категории и EPG. Проверка выполняется загрузкой HLS-манифеста одного канала до сохранения. При ошибке ничего не меняется; ошибка не содержит ключа. Ключ не возвращается в ответе админки и не подставляется обратно в поле. Как и раньше, клиент воспроизведения получает URL канала с авторизацией; NAS рассчитан на доверенную домашнюю сеть.

Начиная с 1.1.4 новая установка использует встроенный шаблон VIO: достаточно ключа доступа. В существующей установке повторный импорт не требуется. После применения ключа старая ссылка автозагрузки отключается, чтобы обновление не вернуло старый ключ. Каталог автоматически из кабинета не синхронизируется; новые каналы подключаются обычным импортом. Новый импорт отменяет режим ключа. Ключ вводите в админке NAS, не отправляйте в GitHub или чат.

## Собственный шаблон и нумерация · 1.1.4

В поставку включён собственный шаблон VIO на 2543 канала в исходном порядке списка владельца проекта. Шаблон хранит только названия, категории, EPG-идентификаторы, номера и публичные идентификаторы потоков; ключей доступа в нём нет. При первом подключении по ключу сервер создаёт адреса из шаблона, проверяет HLS одного канала и только затем сохраняет каталог. Для существующего списка меняется ключ с сохранением идентичности каналов и избранного. Свежий каталог имеет постоянные ID, не зависящие от ключа.

API, браузерный клиент, MSX и Android показывают общие номера каналов от 001. При фильтрации или выборе избранного номера не пересчитываются относительно фильтра. При повторном импорте другого M3U применяется порядок нового файла. Шаблон — снимок каталога, не автоматическая синхронизация кабинета провайдера; доступность всех каналов для произвольного ключа не гарантируется. Не используется каталог OTT-Play.

## VIO Direct · GitHub Pages

Автономный MSX-клиент собирается командой `npm run build:direct` в `_site/`. GitHub Pages публикуется отдельным workflow. Один раз включите Settings → Pages → Source → GitHub Actions в репозитории. После успешного развёртывания параметр MSX: `vioproduct1-sudo.github.io/VIO`. GitHub содержит приложение и шаблон без ключей. Ввод ключа происходит экранной клавиатурой MSX, хранение — localStorage текущего устройства. Ключ не включается в URL GitHub или HTML/JSON страниц. Видео разрешается локальным interaction-плагином и запрашивается напрямую у провайдера. Готовые URL с авторизацией доступны самому плееру MSX и устройству — это необходимо для воспроизведения.

Список, избранное, категории и крупный режим работают на устройстве; NAS, Tailscale и API не требуются. По умолчанию используется встроенный плеер MSX. Дополнительный плеер получает адрес через обмен сообщениями SDK, без передачи ключа в URL страницы GitHub. Телепрограмма XMLTV и настройки серверной админки NAS в Direct не загружаются. Поддержка конкретных потоков, HTTP-видео из HTTPS-плагина и поведение разных ТВ/UWP требуют проверки на устройстве. Direct не синхронизирует ключ между устройствами. Старый стартовый JSON NAS пока остаётся отдельным до проверки нового развёртывания.
